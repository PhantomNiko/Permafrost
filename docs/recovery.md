# Permafrost 0.7 recovery record

The supplied WinterFirmware and UEFI 0.8 images become Permafrost 0.7.
`recovery/reference.json` records reference hashes and native architecture
inventories. The original instructions are analysis inputs, not build inputs.

`kernel/i386` and `kernel/x86_64` contain the recovered implementations,
initialized data, function declarations, and address-to-source ABI maps.
`recovery/kernels` supplies their current link layouts. The i386 EFI reference
uses the same function offsets at a different load address; its profile
relocates address constants and supplies its initialized data without
duplicating the implementation. The 816-function i386
kernel and 814-function x86-64 kernel share freestanding runtime support.

`firmware` contains the C BIOS chain and recovered IA32/x86-64 EFI loaders.
Processor transitions and control-register operations use inline assembly
inside C source. The EFI firmware bridge is compiled C, replacing the original
runtime instruction emitter. PE relocation tables, GPT checksums, FAT32
folders, Mach-O segments, and universal containers are generated by Python
packaging tools.

Each language implementation has one C source set in `applications` and two
architecture profiles in `recovery/applications`. The x86-64 variants use an
ILP32 data model to preserve the verified recovered internal object layouts,
while executing x86-64 instructions and using the SysV register ABI. Compiler
argument lists are marshalled where the original implementation consumes a
packed 32-bit argument stream. Public WMAP records retain 32-bit pointer slots.

Initialized arrays preserve strings, tables, and zero-filled state. Instruction
regions are rebuilt from C. Address-compatible entry stubs transfer to linked
C functions; data references to recovered function entries are rebased during
packaging. Normal builds need neither reference images nor Ghidra.
